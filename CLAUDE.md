## Как работать со мной
- Перед тем как писать код для новой фичи — сначала спроси, как я сам вижу
  решение, или предложи 2-3 варианта с объяснением компромиссов. Не пиши
  сразу готовое решение молча.
- После генерации кода — обязательно объясни, что делает каждая
  нетривиальная часть (особенно: транзакции, блокировки БД, auth-логику,
  фоновые задачи).
- Если видишь, что я не до конца разобрался в объяснении — переспрашивай,
  не продолжай молча дальше.
- Не добавляй библиотеки/паттерны без объяснения, зачем именно они нужны
  здесь, а не альтернатива.

## Архитектурные решения проекта (заполняется по ходу)
- Auth: Session-based (Redis для хранения сессий). Осознанно выбрано вместо 
  JWT — проект монолитный, нет независимых микросервисов, которым нужна была 
  бы stateless-проверка токена без похода в БД.
- БД: PostgreSQL, асинхронный SQLAlchemy
- Ключевая сложность: race condition при одновременном бронировании места
  на сеанс — нужна транзакция с блокировкой, не забывать про это в любой
  логике бронирования
- Модель данных: Кинотеатр→Зал→Сеанс→Фильм; Сеанс→МестоСеанса (справочник 
  БЕЗ поля статуса); Пользователь + МестоСеанса → Бронь (с UNIQUE constraint 
  на место_сеанса_id — здесь и есть race condition); Бронь→ДопУслуги→Оплата

## Что НЕ делать
- Не переписывай архитектурные решения без явного обсуждения
- Не скрывай сложность за "магией" — если что-то неочевидно, проговори это
